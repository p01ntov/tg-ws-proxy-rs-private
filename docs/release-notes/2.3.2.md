# v2.3.2

## End-to-end proxy diagnostics

This release adds an `mtproto_probe` example for measuring a running proxy's
real connection latency. A TCP connect or WebSocket upgrade alone can pass
while the selected route cannot carry Telegram traffic, so the probe sends an
actual unauthenticated `req_pq_multi` request and accepts a sample only after a
matching `resPQ` comes back from Telegram.

The report includes success count, minimum, mean, p50, p95 and maximum latency.
Positive DC indexes test normal connections; negative indexes test the media
route for the same DC. The probe needs no Telegram account or API credentials.

`TG_SECRET` is the only accepted source for the proxy secret. It is not accepted
as a positional command-line argument, keeping it out of normal process-list
output. Plain 16-byte keys and secrets carrying a `dd` or `ee` prefix are
supported.

The stalled-proxy test fixture now stays open beyond the connection timeout it
verifies, preventing an early EOF from making that test timing-dependent.

There are no proxy protocol, routing or runtime changes in this release.
